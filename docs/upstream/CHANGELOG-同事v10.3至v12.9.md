# KOKALabel报价系统 变更日志

## v12.9（2026-10-19，新增「规则匹配」并保留「表格匹配」双模式）

> 基线 v12.8。

### 背景
规格代码（002/003/…/100）此前**完全依赖**纸张规格表的「最大含出血面积 (mm²)」列匹配，
但该列历史数据存在偏差（003/005/055/006/007/009 共 6 个值）；且 v7.3 另有一段硬编码
强制映射（4000–4999→005、5000–5499→055、5500–6000→006），导致 **5000–6000 区间表格数据实际失效**。
故新增一套可编辑的「规则匹配」供切换，原算法保留为「表格匹配」。

### 新增：规格匹配方式（报价设置 → 默认选项）
- 新增下拉「**规格匹配方式**」：**表格匹配（默认）** / **规则匹配**。
- 存 `APP_PROFILE.specMatchMode`，默认 `"table"`；保存后立即重算。
- **默认「表格匹配」= v12.8 原算法逐位不变**（含 v7.3 的 005/055/006 强制映射）。

### 新增：规则匹配（数据管理 → 匹配规则）
- 规则**只决定「用哪个规格代码」，价格仍取纸张报价表中该代码的价格**；
  启用规则匹配时，「最大含出血面积」列不参与匹配。
- 匹配：面积 ≤ 某条规则的「面积上限」即命中；**未命中（超出规则上限 / 该纸没有该代码）自动回退表格匹配**。
- 规则集：**全局一套**（除织唛外的所有报价表）+ **织唛专用一套**；支持在线增删改、恢复默认。
- 默认全局规则：`002=1999、003=2999、004=3999、005=4999、055=5499、006=5999、007=6999、008=7999、009=8999、100=10000`
  （主步长 1000；**055 与 006 各仅 500 宽**）。
- 默认织唛规则：代码即「宽(cm)×长(cm)」，长固定 8cm → **上限 = 宽(cm) × 800**，
  即 `1.3*8=1040 … 5*8=4000` 共 9 档（与其表格完全等价，切换模式不改变织唛报价）。
- 存储：新增 `tagPricing_specMatchRules`（缺失自动补默认，无需 dataVersion 迁移）。

### 说明：规则匹配下 007/008 不再合并显示
- 表格匹配沿用原逻辑，007/008 仍合并显示为 `007/008`；
- 规则匹配按面积精确取 **007（6000–6999）** 或 **008（7000–7999）**；
  两者价格数据完全一致（已核 43/43 张纸）。

### 验证
- `node --check` × 4 通过；回归 `node --test` **6/6 通过**。
- 双向探针（`_probe_spec.mjs`）：
  - 表格匹配与 v12.8 基线 **9 个边界值逐点一致**（3999/4000/4999/5000/5499/5500/6000/6001/7000）；
  - 规则匹配 **19 个边界值全部符合新规则**；
  - 织唛在两种模式下结果完全一致。

## v12.8（2026-10-10，档位缺价/手动邮费红字高亮 + 账号管理卡铺满）

> 基线 v12.7。

- **性能**：档位标记变化时才重建下拉（签名对比），避免每次计算重建造成闪烁。

## v12.6（2026-10-10，保存基于当前状态 + 吊牌成本合计口径与换行 + 手动邮费高亮 + 统计区显示修复）

> 基线 v12.5。五项修复（含一个"保存未含就地修改"的真实缺陷）。

### 修复：保存本次报价未包含就地编辑的临时修改（核心缺陷）
- **现象**：改了折扣 / 工艺费 / 吊绳 / 邮费（就地编辑）后保存，记录仍显示默认值。
- **根因**：`collectQuoteOverride()` 仅收集吊绳/邮费/毛利系数覆盖，**未含 v12.3/v12.4 新增的
  折扣（`discountCache`）/ 工艺费（`craftPriceCache`）/ 批量直接启用态（`batchDirectOnCache`）**，
  记录里的"临时修改"因此缺失。
- **修复**：
  1. 新增 `collectInlineOverrideDetails()` 统一收集三类就地覆盖并合并进记录 override
     （就地覆盖存在但缺少成本/报价摘要时自动补 `newCost`/`pricesByLevel`）；
  2. **载入历史时还原覆盖**（`loadHistoryParameters`）：折扣 / 工艺费 / 批量直接启用态 / 吊绳临时价
     全部恢复到缓存 → **载入后与保存时完全一致**；
  3. 保存提示与历史详情浮窗同步列出"折扣 ×N 处 / 工艺费 N 处 / 批量直接报价 N 张"。

### 修正：吊牌成本合计的口径与行序
- **口径**：原为「成本合计 − 邮费」（仍含吊绳）；现改为「成本合计 − 邮费 − 吊绳」，
  即**吊牌本身成本**。因标准模式下工艺费已并入纸张折后价（v10.2 起），
  该值恒等于「纸张折后价合计（已含工艺费）」——**注意**：若按字面"纸张折后价 + 工艺费"直接相加会
  重复计算工艺（实测示例 138.75 已含 90 工艺，相加得 228.75 为虚高），故实现取正确口径并在标签加悬停说明。
- **行序**：「吊牌成本合计」移到「吊绳费用」上方（悬停说明：不含吊绳与邮费）。

### 新增：快速切换档位——手动邮费档位红框高亮
- 当前地区在某档位的邮费为**手动输入值**时，该档位按钮显示红框高亮（含悬停提示），便于识别。

### 修复：快照与统计报表区显示不全 / 比例失调
- 「热销尺寸」等统计卡标题**永不折行/竖排**（`white-space: nowrap` + 头部 `flex-wrap`）；
- **取消统计区 520px 限高**（原会把「利润分布」等卡片内容裁切，如"累计利润"显示不全）→ 内容完整展示；
- 统计区单栏断点由 920px **提升到 1200px**（中窄屏两栏会挤压统计卡）。
- 实测：700px 视口下已单栏（628.5px），内容 `scrollHeight === clientHeight`（不截断）。

### 验证
- jsdom **18 项全绿**：吊牌成本合计（= 成本−邮费−吊绳 = 纸张折后价合计）/ 结果行序 /
  保存含 discounts+crafts 与提示 / **载入还原（折扣 0.8、工艺 5 恢复，载入后成本与保存时一致）** /
  手动邮费高亮（当前档位、无手动时不误标）/ 统计区 CSS 三条规则。

## v11.9（2026-10-10，布局根因修复：.pages 撑满 + 全页一屏适配）
