# KOKA（原 KOKALabel）吊牌报价系统 · 项目总结文档

> 版本 v10.8.0 ｜ 归档 2026-10-07 ｜ 面向"需要理解全局或做规划"的读者

---

## 一、项目背景与定位

**业务背景**：吊牌 / 织唛 / 唛头类印刷品，报价要素多且互相耦合——纸张材质、印刷工艺、成品尺寸、批量档位、后道（吊绳）、运费，任何一项变化都会影响单价。业务员手工算价慢且容易算错，且不同客户等级对应不同毛利系数。

**产品定位**：一个**报价计算器 + 报价数据管理平台**。核心价值是"输入几个参数就出准确价"，同时让超管能在线维护全公司的价格表并一键同步给所有人。

**使用者**：内部业务员（日常查价）、管理员（维护价格表）。

---

## 二、技术形态与规模

| 维度 | 情况 |
|---|---|
| 形态 | 纯静态前端 SPA（无框架、无构建）+ Cloudflare Pages Functions 后端 |
| 前端 | 原生 HTML/CSS/JS；唯一第三方库是本地化的 SheetJS |
| 后端 | Cloudflare Pages Functions（JS）+ Cloudflare KV（账号 / 会话 / 全局默认数据） |
| 数据 | localStorage 本地持久化 + KV 云端共享 |
| 登录 | 仅网页版强制；`file://` / exe 免登录 |
| 规模 | `data.js` 11193 行、`app.js` 5925 行、`index.html` 1149 行、`style.css` 3813 行 |
| 业务数据 | 45 张纸 / 27 种吊绳 / 9 个邮费地区 / 4 张报价表 / 3 个报价表组 |

**为什么不用框架**：项目要求"双击 html 就能离线用"，任何构建步骤都会破坏这个前提。

## 三、功能全景（v10.8.0 现状）

### 3.1 智能报价计算器（核心页）
- **多纸张同时报价**：一次最多算多张纸，每张纸独立选材质、尺寸、工艺
- **尺寸与面积**：输入长宽 mm，自动算面积并匹配规格代码；出血表自动 +3mm，
  不出血表（唛头类）按实际长宽
- **规格自动取档**：按「最大含出血面积」列向上取档；也可手动用 `▲▼` 切换代码
- **工艺叠加**：按纸张挂载工艺（烫金 / UV / 鸡眼 / 凹凸等），可多选
- **批量档位**：500 / 1000 / 2000 / 3000 / 5000 / 10000 …，不同档位不同单价
- **吊绳**：以 1000 张为基准价，按档位等比放大；含「不加吊绳」免费选项
- **邮费**：按地区 + 档位查表；超 10000 张按重量 × 地区系数；中间档可手输
- **客户等级**：不同等级不同毛利系数，一次算出多档价格
- **直接系数模式**：每张纸独立的最高/最低倍数，中间等级等差插值
- **批量直接报价**：面积在阈值内直接给固定价（不打折、不乘系数）
- **面积系数**：面积超 10000 时用最大规格 × (面积/10000)

### 3.2 报价表组查询
- 按报价表组 / 报价表切换查看价格矩阵
- 支持搜索（代码或面积）
- **价格表就地编辑**：点单元格直接改（有确认框）
- **报价表备注**：顶部独立框体显示当前报价表备注（v10.8.0 新增）
- 在线增删改报价表与分组

### 3.3 个人主页
- 公司信息、默认纸张 / 默认吊绳 / 默认档位
- **个性化字号**：8~32px 可手输，实时显示「当前字号 Xpx（Y%）」
- 数据管理：导出/导入完整配置、导出快照、恢复出厂默认
- 账号管理（超管）：增删账号、改角色、启用停用

### 3.4 账号与云同步（网页版）
- 四级角色：superadmin > admin > sales > visitor
- 「↑ 保存为全局默认」→ 写 KV → 全员 10 秒轮询自动同步
- 会话 TTL 管理，停用即时生效

### 3.5 数据可靠性设计
- **版本迁移链**：老用户 localStorage 自动升级，只补缺失、不覆盖用户数据
- **缺价显式标记**：任一环节缺价 → 整单标"部分缺价"，绝不用 0 凑数
- **报价历史 + 本地快照**：可导出/恢复
- **云端默认数据**：换设备/换浏览器也能拿到最新价格表

## 五、重大决策记录（为什么这么做）

1. **不用框架、不做构建**
   → 为了保住"双击 html 离线可用"。代价是 `app.js` 单文件近 6000 行。

2. **吊绳 / 邮费全局共享，纸张按报价表隔离**
   → 吊绳邮费是全公司统一的采购价，纸张按小组（1楼/3楼/唛头）各管各的。

3. **吊绳价格改「倍数制」而不是逐档填价**（v9.9）
   → 原来 5 个档位要填 5 个数，容易填错又不一致。改成只填 1000 张基准价，其余按比例算。

4. **「是否出血」做成报价表级开关而不是纸张级**（v10.8.0）
   → 一个报价表内部的出血规则是一致的；做成纸张级会让配置变复杂而无实际收益。

5. **不出血表仍读「最大含出血面积」这一列**
   → 保持 Excel 列结构完全不变，只改计算口径。这样同一套 Excel 格式能同时承载两类报价表。

6. **账号体系整体切到 v10.5 四级**（v10.7.1）
   → 外部 v10.7.0 用的是 `admin/sales/guest` 三级，与线上已运行的 v10.5 四级不兼容。
   为避免两套账号体系并存，整体切到 v10.5。（实测 v10.5 的 `auth.js` 与 `functions/` 与目标版本几乎完全一致，移植成本极低。）

7. **不写框架状态管理，全部走 DOM 读取**
   → `calculate()` 直接从 DOM 读当前选中的纸张/吊绳/地区。简单，但**改 DOM 结构时必须同步检查所有 `els.*` 引用**。

## 六、技术亮点

- **单一 `calculate(inputs)` 纯函数**收口全部计价逻辑，渲染与计算分离。
- **迁移链设计**：IIFE 顺序执行 + `dataVersion` 基线守卫，老数据可无损升级。
- **缺价显式化**：`hasMissingTier` / `costKnown` / `costIncomplete` 三态，杜绝"静默算成 0"。
- **Excel 往返**：导出的表可以直接改完再导入，格式与业务同事手工维护的表一致。
- **零依赖离线可用**：SheetJS 本地化，断网也能导入导出。
- **权限门控集中在 `KOKA.canEditQuote()`**，所有就地编辑入口统一拦截。

## 七、踩坑记录（精华教训）

1. **元素 id 与 JS 引用脱钩**（最隐蔽）
   HTML id 从 `personalizeModal` 改名 `personalizePanel`，JS 仍读旧名 →
   `getElementById` 返回 null → `if (els.xxx)` 判空静默跳过 → 表现为"点击无反应"。
   **教训：改 id 必须全局 grep 旧名；null 判空包装会隐藏真实故障。**

2. **把合法 0 当成"没填值"**
   吊绳 `getRopeBasePrice()` 对 `≤0` 一律返回 null → 「不加吊绳」全 0 价被误判缺价。
   **教训：区分"显式 0"与"未设值"要用 `null` 而不是 `0` 表示缺失。**

3. **重渲染时用默认值覆盖用户选择**
   `rebuildRopeUI()` 重渲染吊绳单选时按 `APP_PROFILE.defaultRope` 重置选中项，
   把用户选的吊绳悄悄换回默认；而调用顺序是"先 rebuild 再算价" → 算错。
   **教训：局部重渲染必须保留用户当前状态。**

4. **重写 DOM 后忘记重绑事件**
   `initOptions()` 重写 `els.rope.innerHTML` 却没重新 `bindRopeEvents()` →
   之后所有吊绳切换失效。**教训：innerHTML 重写 = 事件全丢。**

5. **版本号更新的正则坑**
   `"version": "10.7.0"` 还有无空格变体 `version: "10.7.0",`，纯字符串替换会漏。

6. **`dataVersion` 与界面版本号混用**
   早前用同一串表示两者，导致迁移守卫被污染、后续迁移全跳过。现已分离。

7. **行尾符污染**
   编辑工具 / python `write_text()` 会静默把 LF 转 CRLF，`diff` 出现上万行噪音
   （曾把 69 行真实差异放大成 10129 行）。项目统一 LF。

8. **Edge headless 验证前端不可信**
   `--dump-dom` 在 DOMContentLoaded 就快照，body 末尾的探针脚本根本不执行 →
   会把正常代码误判成"功能坏了"。改用 **jsdom + 同进程静态服务器**。

9. **`.git` 对象库损坏的救援**
   `.pack` 丢失后 loose 对象也丢了 → 本地历史残缺。
   **正解：远端才是真相来源**，重新 clone 再把改动叠上去；
   抢救前先抄录 `.git/packed-refs`（克隆不带本地独有分支，事后要靠它重建）。

10. **部署把内部文档一起传上去了**
    早期部署源包含 `docs/`、`tests/`、`问题日志.md`，这些能被公开访问。
    现已改为**干净的部署目录**（只带站点必需文件）。

## 十、一句话给接手者

这是一套**没有构建步骤、数据全在前端、靠一条迁移链兼容历史**的报价工具——
改代码前先跑 `node _verify/v1080.test.cjs` 建立基线，改完再跑一次；
改 DOM 结构时记得同步 `els.*` 引用；改完要部署记得**必须用 wrangler v3**。
