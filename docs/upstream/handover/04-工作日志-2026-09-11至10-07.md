### ★ 仓库救援（本次最大插曲）
1. 发现本地 `.git` **对象库损坏**：`objects/pack/` 只剩 `.idx`，`.pack` 丢失，
   loose objects = 0，`refs/heads` 空 → `fatal: bad object HEAD`。
2. **回收站救命**：在 `C:\$Recycle.Bin\...\$RCAWPMO.git\` 找到完整 `.git`，
   复制回 pack/rev 后 `verify-pack` → `ok`。但该 pack 只覆盖到 v9.4.0(09-08)，
   之后的对象已永久丢失。
3. **正解：远端才是真相来源** → 从 GitHub 重新 clone（远端 main 仍是 v10.5.0，历史完整），
   再把 v10.7.1 文件叠上去重新提交。
4. **沙箱丢写**：非提权调用会静默丢弃对 `.git/refs/**` 的写入 → `refs/` 反复消失 →
   git 报 `not a git repository`（即使 `.git` 完整）。对策：写操作关沙箱 + 引用固化到 `packed-refs`。
5. **`git merge` 会 SIGTERM 挂起** → 改用 plumbing（`write-tree` + `commit-tree` + 直接写 refs）。
6. **`git -F /tmp/x` 必失败** —— 原生 Win 程序不认 MSYS `/tmp`，要用 Windows 原生路径。
7. **网络**：本地代理必失败、curl 全程 000，只有"绕代理 + 固定 IP + git schannel"能通，
   且时通时断，必须重试循环。

### 晚：仓库分支拓扑恢复
- 用克隆体替换 `.git` 后，本地**只剩 `main` + `v10.7-dev` 两个分支**（原仓库有 26 个）。
- 从 `origin/*` 恢复 12 个；再按损坏前抄录的 `packed-refs` SHA 恢复 13 个历史本地独有分支
  → **13/13 全部命中，0 缺失**（这些 tip 恰是远端 tag 的祖先，随 clone 一并下载了）。
- 修正陈旧的 `origin/main`（原停在 v10.5.0，害得 `git status` 误报 `ahead 2`）。

## 每日惯例（接手后请延续）

1. **动手前**：读 `.workbuddy/memory/MEMORY.md` 与最近几天的日志，避免重蹈坑位。
2. **改代码前**：先跑一次 `node _verify/v1080.test.cjs` 建立基线（21 项应全绿）。
3. **改代码时**：
   - 改 DOM 结构 → 同步检查所有 `els.*` 引用（防 id 脱钩）
   - 改完检查行尾符必须 LF（`\r\n` 计数应为 0）
   - `node --check` 前端 JS + `functions/**/*.js`
4. **改完后**：再跑回归测试；必要时补新断言。
5. **发布时**：更新版本号（python 精确替换，勿用 sed）→ 写 CHANGELOG → git 提交推送
   （plumbing + 组合A）→ 生成干净部署源 → wrangler v3 部署 → 线上三项校验。
6. **收尾**：写当日工作日志到 `.workbuddy/memory/YYYY-MM-DD.md`；重大决策/坑位补进
   `.workbuddy/memory/MEMORY.md`；清理临时脚本，扫描确认无凭据残留。
