## 一、项目一句话概述

给吊牌/织唛类印刷品做**多纸张、多工艺、多批量档位**的快速报价工具，支持本地免登录使用与网页版多人协作（账号分级 + 云端共享默认报价数据）。

## 四、技术架构

### 4.1 前端（无框架、无构建）

纯静态：`index.html` + 原生 JS + 原生 CSS。**没有打包步骤**，改完直接刷新即可。唯一的第三方库是本地化的 SheetJS（`js/vendor/xlsx.full.min.js`），用于 Excel 导入导出。

### 4.2 数据层（localStorage）

`js/data.js` 用 `loadFromStorage(key, default)` 从 localStorage 读，读不到就用内置默认值。关键 key：

| key | 内容 |
|---|---|
| `paperConfig` | 纸张配置（45 张纸，每张含多档规格 × 多档位价格矩阵） |
| `craftConfig` | 工艺配置（按纸张 id 分组） |
| `ropeConfig` | 吊绳配置（27 种，全局共享） |
| `shippingConfig` | 邮费配置（9 个地区） |
| `customerLevels` | 客户等级（毛利系数） |
| `priceLists` | 报价表（4 张） |
| `priceListGroups` | 报价表组（3 个） |
| `currentPriceListId` | 当前报价表 |
| `dataVersion` | **迁移基线**（当前 `10.8.0`，见 4.3） |
| `appProfile` | 个人偏好（默认纸张/吊绳/字号等） |

### 4.3 版本迁移链（`data.js` 尾部，IIFE 顺序执行）

老用户 localStorage 里是旧结构，靠一串自执行的 `(function migrateXXX(){...})()` 逐级补齐。每个迁移内部的守卫是：

```js
const dataVersion = loadFromStorage("dataVersion", "");
if (verCompare(dataVersion, "X.Y.Z") >= 0) return;   // 已升过就跳过
...
saveToStorage("dataVersion", "X.Y.Z");               // 升基线
```

**⚠️ `dataVersion` 与界面版本号含义不同**，不要用改版本号的脚本连带改它。
**⚠️ 新增/修改迁移时，务必只补缺失项、不覆盖用户已有数据**（否则会抹掉用户的本地编辑）。

### 4.4 云端体系（网页版）

- **账号**：Cloudflare KV `KOKA_AUTH`，键前缀 `u:`（用户）/ `s:`（会话）/ `q:v1`（全局默认报价数据）。
- **分级**：`superadmin(3) > admin(2) > sales(1) > visitor(0)`，判定函数 `KOKA.roleNum()` / `roleRank()`。
  - 访客：只能用计算器
  - 业务员：全页只读
  - 管理员及以上：可编辑报价数据
- **默认数据云端共享**：超管点「↑ 保存为全局默认」→ 写 KV `q:v1` → 所有角色 **10 秒轮询自动同步**（覆盖本地 + reload）。
- **端点**：`/api/quote`（默认数据）、`/api/auth/*`（登录态）、`/api/admin/users*`（账号管理）。

## 六、关键业务规则（改逻辑前必读）

1. **面积计算**
   - 出血表：`面积 = (长+3) × (宽+3)`
   - 不出血表（`bleed:false`）：`面积 = 长 × 宽`
2. **规格匹配**：取表格「最大含出血面积」列中**最小的 ≥ 实际面积**那档（向上取档）。
   出血的表还会先走 `forceSpecByArea()` 的强制映射：面积 4000–4999→`005`、5000–5499→`055`、5500–6000→`006`（吊牌专用，不出血的表跳过）。
3. **面积系数**：面积 > 10000 时用最大规格，`系数 = 面积/10000`（保留 2 位）。
4. **吊绳计价**：以 **1000 张为基准价**，500 张同价，其余 `基准价 × 档位/1000`。
   **全 0 价的吊绳视为「不加吊绳」这类免费选项，不报缺价**（`isFreeRope()`）。
5. **成本构成**
   - 标准模式：`纸张(已含工艺，折扣后) + 吊绳 + 邮费 + 批量直接报价合计`
   - 直接系数模式：`纸张 + 工艺` 再乘各自直接系数
6. **缺价标记**：纸张/工艺/吊绳/邮费任一缺价 → `hasMissingTier = true` → 整单标记「部分缺价」，不用 0 凑数。
7. **报价表隔离**：纸张按报价表隔离；**吊绳/邮费全局共享**，不随报价表切换。

## 八、GitHub 推送 SOP（有坑，必须按此操作）

仓库：`https://github.com/zly62612364469/kokalabel-quote`（**私有**）

### 8.1 本机网络是三重的坑

1. 环境注入了本地代理 `http_proxy=http://127.0.0.1:19134`，走它必失败（`CRYPT_E_NO_REVOCATION_CHECK`）。
2. `hosts` 把 `github.com` 解析到本地假服务，**必须用 `curloptResolve` 固定真实 IP**。
3. 直连**时通时断**（成功率约 1/10 ~ 1/2）→ **必须写重试循环**。
   `curl` 全程返回 000 不可用，只有 git 的 schannel 路径能通。

### 8.2 唯一可用命令形态

```bash
env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY \
  git -c http.schannelCheckRevoke=false \
      -c http.curloptResolve="github.com:443:20.205.243.166" \
      push "https://x-access-token:<PAT>@github.com/zly62612364469/kokalabel-quote.git" \
      "refs/heads/main:refs/heads/main" \
      "refs/heads/vX.Y-dev:refs/heads/vX.Y-dev" \
      "refs/tags/vX.Y.Z:refs/tags/vX.Y.Z"
```

- 提交信息文件**必须用 Windows 原生路径**（如 `E:/报价系统7.9/_msg.txt`）——
  `git.exe` 是原生 Win 程序，不认识 MSYS 的 `/tmp`。
- 本地已有同名 tag 时普通 push 被拒 → 需要 `push --force refs/tags/X:refs/tags/X`。
- 推完**务必 `ls-remote` 回读校验**，不要只看返回码。

### 8.3 ⚠️ 当前 PAT 状态（2026-10-07）

**旧 PAT 已失效**（`ls-remote` 报 `Invalid username or token`）——
这是此前"凭据曾在对话中暴露、建议轮换"的后续处理结果，属预期。

**接手后请重新生成 PAT**（需 `repo` 权限；fine-grained token 需 `Contents: Read and write`），
并用上面 8.2 的命令形态推送。

### 8.4 提交建议用 plumbing（本机 `git merge` 会挂）

本机执行 `git merge` 会 SIGTERM 挂起，改用 plumbing：

```bash
git add -A
TREE=$(git write-tree)
NEW=$(git commit-tree "$TREE" -p <parent_sha> -F "E:/报价系统7.9/_msg.txt")
printf '%s\n' "$NEW" > .git/refs/heads/main
printf '%s\n' "$NEW" > .git/refs/tags/vX.Y.Z
git pack-refs --all
```

### 8.5 沙箱写 `.git/refs` 会被丢弃

非提权调用会**静默丢弃**对 `.git/refs/**` 的写入 → `refs/` 反复消失 → git 报
`fatal: not a git repository`（**即使 `.git` 目录本身完整**）。
对策：所有写 `.git` 的操作都在**关掉沙箱**的情况下执行，并把引用固化到 `packed-refs`。

## 九、版本管理规范（血泪教训）

1. **改版本号禁用 `sed` 全局替换** —— 曾多次静默失败。用 python 精确替换，
   并注意无空格变体（`"version": "10.7.0"` vs `version: "10.7.0",`）。
2. **`dataVersion` 基线不要跟着版本号改** —— 迁移守卫会被污染导致后续迁移全跳过。
3. **全项目行尾符必须 LF** —— 编辑工具改写时可能静默转 CRLF，`diff` 会出现上万行噪音。
   ⚠️ **python `Path.write_text()` 在 Windows 上默认转 CRLF**，必须用 `write_bytes()`
   或 `open(..., newline="\n")`，改完再扫一遍 `\r\n`。
4. **移动/删除 DOM 后必须做标签栈配对校验**（曾漏 1 个闭合）。
5. **元素 id 与 JS 引用脱钩是最隐蔽的 bug** —— 曾因 HTML id 改名而 JS 仍读旧名，
   `getElementById` 返回 null 被 `if (els.xxx)` 静默吞掉，表现为"点击无反应"。
   改 id 后**必须全局 grep 旧名**。
6. **改动后跑回归测试**：`node _verify/v1080.test.cjs`（21 项，全绿为准）。
7. 验证优先用 **jsdom**（同进程起静态服务器 + `JSDOM.fromURL`），**不要用 Edge headless**
   （`--dump-dom` 在 DOMContentLoaded 就快照，body 末尾脚本根本不执行，会误判功能坏了）。
8. jsdom 里注意：`data.js`/`app.js` 顶层用的是 `let/const`，**不会挂到 `window`**，
   要用 `window.eval("ROPE_CONFIG[0]")` 取值。

## 十一、常见任务操作手册

### 改价格（最常用）
1. 网页版用超管登录 → 「报价表组查询」页 → 点价格单元格直接改（会弹确认框）
2. 改完**必须点「↑ 保存为全局默认」**才会写云端，其他账号才能看到

### 新增一张报价表
两种方式：
- **Excel 导入**：按模板填好后导入（会新建一张报价表），或"按模板原地覆盖"已有表
- **在线管理区**：直接新建 + 改名 + 移动分组

### 批量改价
导出 Excel → 改 → 导入。**注意导出/导入的往返格式**：

```
所属小组 / 总报价表 / 报价表全称 / 简称 / 折扣系数 / 是否出血
直接系数档位 / 最高倍数 / 最低倍数
批量直接报价最大面积 / 批量直接报价档位 / 批量直接报价价格
备注
（空行）
代码 / 最大含出血面积 / 档位1 / 档位2 / ...
（数据行）
（空行）
工艺名称 / 档位1 / ...
```

### 加一条数据迁移
在 `data.js` 尾部的迁移区追加 IIFE，参考 `migrateV1080BleedAndMaitou` 的写法。
