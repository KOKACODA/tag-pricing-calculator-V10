## 一、总览：一次报价的数据流

```
用户操作（选纸张/改尺寸/点档位/就地改价…）
        │  每次操作触发
        ▼
onCalculate()  (app.js:1657)
  ├─ 收集输入：sheetCount / tier / ropeId / regionId / sheets[]（纸id+工艺+长宽）
  ├─ 邮费缺档检测 → 弹重量/手动邮费对话框（会话级缓存）
  ├─ 覆盖注入：ropePriceCache / shippingPriceCache（就地修改的临时价）
  ▼
calculate(inputs)  (app.js:476)   ← 纯函数，全部计价在这里
  ├─ 逐纸：面积 → 取档 → 纸价(含工艺) → 缺价标记
  ├─ 吊绳费（倍数制）/ 邮费（三模式）/ 成本合计
  ├─ 各客户等级报价 pricesByLevel[]
  ▼
渲染层（纯展示）：结果行 / 报价卡片 / 明细表 / 警告
  │
  ├─ 临时毛利系数输入 → 只在前端重乘，不改 _lastResult.cost
  └─ 保存报价 → _lastResult 快照 + override 明细 → localStorage
```

**核心原则**：计算与渲染分离；`calculate()` 不碰 DOM；缺价绝不用 0 凑数（三态标记）。

## 二、计价引擎逐步拆解（`calculate()` app.js:476-813）

### 第 1 步：面积（app.js:519-521）

```
出血表（默认）：面积 = (长+3) × (宽+3)
不出血表（唛头）：面积 = 长 × 宽        ← bleed 字段，报价表级开关（v10.8.0）
```

### 第 2 步：规格取档（app.js:416-475）

v12.9 起有**两种匹配方式**，由 `APP_PROFILE.specMatchMode` 决定（报价设置 → 默认选项，**默认表格匹配**）：

**A. 表格匹配（`table`，默认）**

```
① 强制映射（仅出血表）：4000-4999→005；5000-5499→055；5500-6000→006（硬编码，吊牌专用）
② 常规取档：specs 里找 maxArea ≥ 面积 的最小那档（向上取档）
③ 面积 > 全部规格 → 用最大规格 code"100"，并乘面积系数 = 面积/10000（保留2位）
④ 手动代码（▲▼切换）走 findSpecDisplayCode（007/008 合并显示）
```

**B. 规则匹配（`rule`）**

```
① 按「数据管理 → 匹配规则」的规则集（全局 / 织唛专用），
   面积 ≤ 该行「面积上限」即命中 → 取该代码
② 价格仍取纸张报价表中该代码的价格（规则不携带价格）
③ 未命中（超出规则上限 / 该纸无此代码）→ 回退到 A 的 ②③
④ 007 / 008 按面积精确取（6000-6999→007，7000-7999→008），不再合并显示
```

默认规则：`002=1999、003=2999、004=3999、005=4999、055=5499、006=5999、007=6999、008=7999、009=8999、100=10000`
（主步长 1000；**055 与 006 各仅 500 宽**）；织唛为 `1.3*8=1040 … 5*8=4000`（上限 = 宽(cm) × 800）。

### 第 3 步：纸价（app.js:584-608）

```
有直接系数的纸（直接模式）：原价（不打折）
标准模式：(规格价 + 工艺费) × 折扣系数 × 面积系数
批量直接报价（paper.batchDirect 配置）：面积 ≤ maxArea 时直接用固定价（不打折不乘系数），
                                         该纸的工艺费也单独直接叠加
```

### 第 4 步：吊绳费（app.js:634-660）

```
基准价 = prices["1000"]（缺失回退 500 档；全 0 价 = 合法免费项 isFreeRope）
吊绳费 = 基准 × (档位 ≤ 1000 ? 1 : 档位/1000)      ← 倍数制（v9.9）
就地修改：ropePriceCache[ropeId_tier] 覆盖（v10.9.0）
```

### 第 5 步：邮费（app.js:663-700，三模式）

```
A 固定档：basePrices[tier] 有值 → 直接查
B 重量档：tier > 10000 → 吊牌重量(kg) × region.overTierCoeff
C 手动档：中间档（2500/3000…）→ 弹窗手动输入（manualShippingCache 会话缓存）
就地修改：shippingPriceCache[regionId_tier] 覆盖（v11.0）
```

### 第 6 步：成本与缺价三态（app.js:692-704）

| 状态 | 含义 | 触发 |
|---|---|---|
| `hasMissingTier` | 任一纸/工艺/吊绳/邮费在当前档无价 | 任一环节缺价 |
| `costKnown` | 成本可信（= !hasMissingTier） | 标准模式 |
| `costIncomplete` | 整单"部分缺价"，**绝不用 0 凑数** | = !costKnown |

⚠️ 已知例外（P2 待修）：直接系数模式强制 `costKnown=true`，缺价时成本合计仍显示数字（审查报告 #6）。

### 第 7 步：客户等级报价（app.js:706-789）

```
标准模式：pricesByLevel = 各等级 cost × level.coefficient
直接系数模式：每纸独立——有直接系数的纸 (纸价+工艺) × 系数（max→普通客户，min→大客户，中间等差插值，
             保留2位）；无直接系数的纸 × 折扣；批量直接纸固定价直接累加
```

### 第 8 步：直接系数取值（app.js:347-373）

```
Excel 表三行「直接系数档位/最高倍数/最低倍数」→ 找 ≤ 所选档位的最大档位 →
等差插值：coefficient(i) = round((max - (max-min)/(n-1)*i) × 100)/100
⚠️ 已知舍入偏差（P3）：1.275 会显示 1.27
```

## 三、后端 API（前端完全看不到的部分）

全部在 `functions/`（Cloudflare Pages Functions，KV 绑定名 `AUTH`）：

| 端点 | 方法 | 权限 | 作用 |
|---|---|---|---|
| `/api/auth/login` | POST | 公开 | PBKDF2(10万次+盐) 校验；**无速率限制**；区分"账号不存在/密码错误"（可枚举） |
| `/api/auth/session` | GET | Bearer | 会话校验，**每次实时回查用户**（停用/过期即时生效） |
| `/api/auth/status` | GET | 公开 | 是否已初始化（登录页用） |
| `/api/quote` GET | GET | 登录即可 | 读全局默认报价数据（KV `q:v1`，全员 10 秒轮询） |
| `/api/quote` POST | POST | **仅超管** | 全量覆盖写 `q:v1`（4 个配置段，无结构校验） |
| `/api/admin/users` GET/POST | — | 管理员+ | 列账号 / 创建（角色白名单 + canManage 分级） |
| `/api/admin/users/[name]` PATCH/DELETE | — | 见下 | 改密/昵称/时长/启停/角色/删除（不能自删自停；至少保留 1 管理员） |

**会话**：随机 32 字节 token 存 KV `s:*`，TTL 7 天；Bearer 头传输（不走 cookie，CSRF 面小）。
**密码**：PBKDF2-SHA256 10 万次迭代 + 16 字节随机盐（OWASP 现行推荐 60 万次，可提升）。
**已知安全待办**：admin 弱密码 + 登录限速（上线前必做，用户已确认测试期跳过）；改密后旧会话不失效。

**权限矩阵**（`canManage`，_lib.js:96-101）：

| 角色 | 可管理对象 |
|---|---|
| superadmin(3) | 全部 |
| admin(2) | sales/visitor/admin（互管，不能动 superadmin） |
| sales(1) / visitor(0) | 仅自己（改昵称/密码） |

## 四、存储结构（前端看不到的持久层）

### localStorage（键前缀 `tagPricing_`，浏览器 5MB 上限）

| key | 内容 | 规模 |
|---|---|---|
| `paperConfig` | 全部纸张（45 张，含 specs 价格矩阵） | 最大，数百 KB |
| `craftConfig` | 工艺（按纸张 id 分组） | |
| `ropeConfig` / `shippingConfig` | 吊绳 27 / 邮费 9 地区（**全局共享**） | |
| `priceLists` / `priceListGroups` | 报价表 3 张 / 组 3 个（v11.4 唛头已合并） | |
| `currentPriceListId` / `currentCalcMode` | 当前状态 | |
| `customerLevels` | 客户等级毛利系数 | |
| `dataVersion` | **迁移基线**（≠界面版本号） | 当前 11.4 |
| `appProfile` | 个人偏好（公司/默认项/小数位/`specMatchMode` 匹配方式） | |
| `specMatchRules` | **v12.9**：规格匹配规则集（`{global:[...], <织唛报价表id>:[...]}`，仅本地，未云同步） | 极小 |
| `quoteHistory` / `snapshots` | 报价历史 / 配置快照 | 可增长到 MB 级 |

### 迁移链（data.js 尾部，IIFE 顺序执行）

```
每个迁移：读 dataVersion → verCompare 与基线比较 → 只补缺不覆盖 → 最后写新 dataVersion
v5.4 → v8.0（重置结构，v11.3 补守卫）→ v8.4 → v9.0.1 → v9.5.1 → v9.9 → v10.8.0 → v11.4（唛头合并）
```

⚠️ 迁移"先写数据后写基线"✓（中断不会半新半旧）；但**无整体事务**——极老数据跨 8 个迁移，任何一步的默认数据变化都会被固化。

### 云端同步（网页版）

```
超管「保存为全局默认」→ POST /api/quote（全量 4 段）→ KV q:v1
所有登录用户每 10 秒 GET /api/quote → updatedAt 变化 → 覆盖本地 localStorage → reload
⚠️ 覆盖是全量的：本地未发布的修改会被云端版本冲掉（设计取舍，界面有提示）
```

## 五、优化建议清单（按收益/代价排序）

### A. 计价性能（calculate 热路径）

| # | 现状 | 建议 | 收益/代价 |
|---|---|---|---|
| A1 | `getPapersByPriceList(CURRENT_PRICE_LIST_ID).find(...)` 在**每纸循环和每等级循环**内重复执行（app.js:515、714 等），45 纸 × 33 表纸 = 每次报价上千次数组扫描 | calculate 开头建一次 `Map(paper.id → paper)`，循环内 O(1) 取 | 大配置下明显提速；代价低（10 行改动） |
| A2 | 直接系数模式 pricesByLevel 每等级重复 `find` 同样的纸 | 同上，Map 复用 | 同上 |
| A3 | `localStorage.setItem` 全量序列化数百 KB（每次保存配置） | 频率低（有确认框），暂不动 | 低 |

### B. 数据健壮性

| # | 现状 | 建议 | 收益/代价 |
|---|---|---|---|
| B1 | Excel 导入接受负价格（4 处） | 导入时 `price < 0` 拦截报错 | 防手误护栏；代价极低 |
| B2 | `hasExactTier` 把空白字符串 `" "` 当 0 价 | 加 `String(v).trim()===""` 判空 | 防 Excel 空格单元格；代价极低 |
| B3 | JSON 导入（完整配置/本地备份）不校验 specs/prices 结构 | 导入前深拷贝 + 结构断言，不满足整体拒绝 | 防损坏文件搞瘫页面；中等 |
| B4 | 迁移链无整体事务 | 现状"先写数据后写基线"已够用；若做建议加迁移前自动快照 | 低 |

### C. 云同步与网络

| # | 现状 | 建议 | 收益/代价 |
|---|---|---|---|
| C1 | 所有登录用户每 10 秒**全量拉取** /api/quote（数百 KB×人数） | 新增 `GET /api/quote/updated` 轻量端点（只返回 updatedAt），变了才拉全量 | KV 读流量降 95%+；中等 |
| C2 | 云端发布覆盖本地未发布修改 | 检测到本地有未发布修改时弹确认而非直接覆盖 | 防数据丢失；中等 |
| C3 | 云同步 reload 丢失正在填写的表单 | reload 前检测表单是否有输入 | 体验；低 |

### D. 架构

| # | 现状 | 建议 | 收益/代价 |
|---|---|---|---|
| D1 | app.js 6232 行单文件 | **无构建约束下**可拆为 `js/calc.js`（纯计算）/ `js/ui.js`（渲染）按序 `<script>` 引入——不引入打包器仍满足"双击可用" | 可维护性大增；需回归验证 |
| D2 | localStorage 5MB 上限（报价历史最占空间） | 历史记录超 100 条自动归档导出 | 防爆仓；低 |

### E. 安全（上线前必做，测试期已确认跳过）

| # | 现状 | 建议 |
|---|---|---|
| E1 | admin 密码 123456789 | 上线前改强密码（个人主页即可改） |
| E2 | 登录无速率限制 + 用户名可枚举 | KV 计数限速（5 次锁 15 分钟）+ 统一错误文案 |
| E3 | PBKDF2 10 万次迭代 | 提升至 60 万（保留旧哈希兼容迁移） |
| E4 | 改密后旧会话 7 天仍有效 | user 加 sessionVersion 字段校验 |
