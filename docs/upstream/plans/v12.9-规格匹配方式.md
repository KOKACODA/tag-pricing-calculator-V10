## 一、问题背景

规格代码（002/003/…/100）原**完全依赖**纸张规格表的「最大含出血面积 (mm²)」列匹配。实测存在两层问题：

1. **表格数据有偏差**（6 个值）：

| 代码 | 原值 | 规则值 |
|---|---:|---:|
| 003 | 3164 | 2999 |
| 005 | 5500 | 4999 |
| 055 | 6000 | 5499 |
| 006 | 6264 | 5999 |
| 007 | 7999 | 6999 |
| 009 | 9064 | 8999 |

2. **v7.3 硬编码强制映射**（`forceSpecByArea`）：4000–4999→005、5000–5499→055、5500–6000→006。
   与表格数据在 **5000–6000** 区间冲突，导致该区间「最大含出血面积」列实际失效，且报价偏高约一档。

## 二、决策（委托方 2026-10-19 确认）

| # | 决策 |
|---|---|
| 1 | **保留** v7.3 硬编码，归入「表格匹配」内部 |
| 2 | 规则集：**全局一套 + 织唛单独一套**（不按报价表三套） |
| 3 | 规则编辑入口：**数据管理 → 匹配规则** |
| 4 | 规则**只决定代码**，价格仍取表格；「最大含出血面积」列在规则模式下不参与 |
| 5 | 织唛规则沿用其现有 9 档（等价于表格） |
| 6 | **默认启用表格匹配**（保证上线不改变任何现有报价） |

## 三、实现

### 3.1 数据层 `js/data.js`
- `APP_PROFILE.specMatchMode`（`"table"` 默认 / `"rule"`）+ 旧配置容错
- `DEFAULT_SPEC_MATCH_RULES_GLOBAL`（10 档）、`DEFAULT_SPEC_MATCH_RULES_MAITOU`（9 档）
- `SPEC_MATCH_RULES`（`tagPricing_specMatchRules`），结构：`{ global: [...], <织唛报价表id>: [...] }`
- 函数：`getMaitouPriceListId()` / `getSpecMatchMode()` / `getSpecRulesFor()` / `setSpecRules()` / `matchSpecByRules()`
- 无 `dataVersion` 迁移（缺失键由 `loadFromStorage` 默认值 + 结构容错补齐）

### 3.2 匹配层 `js/app.js`
`matchSpec(paper, area, skipForce)`：

```
if (mode === "rule") {  byRule = matchSpecByRules(paper, area);  if (byRule) return byRule;  // 未命中→下落
} else if (!skipForce) {  forced = forceSpecByArea(paper, area);  if (forced) return forced; }
// 表格逻辑（原样）
```

调用点两处**同源**：`L535`（计价主流程）、`L1724`（连续档位判断）。

### 3.3 界面
- 报价设置 → 默认选项：`<select id="specMatchMode">`
- 数据管理 → 新增标签页「匹配规则」：`#panel-rules`、`#ruleSetSelect`、`#rulesTbody`、`#rulesAddBtn`、`#rulesResetBtn`、`#rulesStatus`
- 事件：`change` 保存并重算；`click` 删除；新增/恢复默认
