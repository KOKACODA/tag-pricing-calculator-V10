# v11.9 布局根因修复与一屏适配（计划文档）

> 编制：2026-10-10 ｜ 状态：**已实施** ｜ 用户硬约束（四条）：① 尽量一屏不滚动；② 框体比例合适不留大面积空白；③ 字体不能被压小；④ 同排框体比例自适应匹配

## 一、根因（真实浏览器实测，非推测）

用 Playwright + 系统 Edge 实测（视口 1920×1080，可用内容区 1720px）：

| 页面/视图 | `.pages` 实测宽 | 结论 |
|---|---|---|
| 报价表组查询 · 吊绳/邮费子视图 | **575px** | 只占 1/3，右侧 1145px 空白（用户截图 2/3） |
| 报价表组查询 · 报价表视图 | ~1265px | 仍不足 |
| 智能报价计算器 | 1653px | 接近但未满 |
| 数据管理 / 报价设置 / 个人主页 | 1720px | v11.7 加的 `display:grid` 恰好撑开（grid item 默认 stretch），掩盖了问题 |

**根因**：`.app-shell` 是 `display:flex` 容器；`.sidenav` 为 `position:fixed`（脱离文档流），`.pages` 成为**唯一 flex 子项**，其 `width:auto` 时按**内容固有宽度收缩适应（shrink-to-fit）**——内容少的视图（吊绳/邮费表列少）宽度塌缩到 575px。
此前 v11.2/v11.5/v11.7 反复调 `max-width` 均未触及此点，故"改了多次仍不好"。

**行业标准解法**（调研确认，flex 布局经典问题）：flex 子项显式 `flex: 1 1 auto` + `min-width: 0`，占满剩余空间。

## 二、修复方案

### 2.1 核心修复（一行，牵一发动全身）
```css
.app-shell > .pages, .pages { flex: 1 1 auto; min-width: 0; }
```
效果：全部页面 `.pages` 恒等于可用宽度 1720px（不再随内容收缩）。

### 2.2 数据管理页（用户点单）
- 历史报价记录**固定 9 条**：`#page-data .history-table-wrap { max-height: 508px }`（表头 40 + 9×52），超出内部滚动，新建在上。
- **双栏等高**：`#page-data.active { align-items: stretch }`（原 start → 右侧快照统计卡与左侧数据管理卡齐高，消除参差）。

### 2.3 报价表组查询页
- 撑满后表格自然全宽（`table width:100%`），吊绳/邮费表右侧空白消除；
- 矩阵表 8 档在 1720px 下更舒展，列不再拥挤。

### 2.4 个人主页
- **双列等高**：`#page-profile.active { align-items: stretch }`（消除截图 5 的参差错落）。

### 2.5 明确不做（保护用户约束）
- **不做任何字号缩放**（用户强调字体清晰优先）；
- 不做 `transform: scale` 类强制缩放（会导致模糊）；
- 密度三档保留（用户可选，默认标准不影响可读性）。

## 三、验收标准（浏览器复测）
1. 四页 + 查询页三子视图的 `.pages` 宽度 = 可用宽度（1720±10），**无 > 100px 的右侧空白**；
2. 吊绳/邮费表宽度 ≥ 1500px；
3. 数据管理历史表可视区 ≈ 9 条；
4. 个人主页两列卡片等高（高度差 = 0）；
5. 四页主内容高度 ≤ 视口可视高度（约 1050px，1080 屏一屏）；
6. 字号与 v11.8 完全一致（不改 font-size）。
