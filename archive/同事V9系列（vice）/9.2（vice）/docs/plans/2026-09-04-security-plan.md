## 一、现状安全评估

### ✅ 已有基础
| 项目 | 现状 |
|---|---|
| CSP 内容安全策略 | `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self'`（已较严格） |
| 动态执行 | 无 `eval` / `new Function` / `document.write` |
| XSS | 71 处 `innerHTML` 中约 64 处已用 `escapeHtml` 转义 |
| 攻击面 | 纯前端无后端接口，离线 file:// 运行，外部攻击面小 |

### ⚠️ 现状弱点（按风险排序）
| # | 风险 | 说明 | 优先级 |
|---|---|---|---|
| 1 | **无授权机制** | 任何人拿到 exe/网页都能用，无法控制客户、有效期 | 🔴 高（业务需求） |
| 2 | **localStorage 可篡改** | 价格/激活状态明文存浏览器，懂技术者可用 DevTools 直接改价 | 🟠 中 |
| 3 | **导入文件无校验** | Excel/JSON 导入未限制文件类型/大小，异常文件可致解析异常 | 🟠 中 |
| 4 | **部分 innerHTML 未转义** | 导入的纸名/工艺名若含特殊字符可能注入 HTML（实际由导入方控制，风险较低但需审计） | 🟡 低-中 |
| 5 | **file:// 无法防逆向** | 双击运行无沙箱，JS 逻辑可被阅读/篡改，无法做到绝对防破解 | 🟡 已知限制 |
| 6 | **CSP connect-src 'self'** | 未来加"在线激活"需放开对后端域名的连接 | 🟡 规划前提 |

## 二、安全目标与威胁模型

**目标**：让客户"没密钥用不了、到期用不了"，同时保证正常使用体验（激活一次、离线可用）。

**威胁模型**（按需防范）：
1. 普通用户直接拷贝使用 → **密钥门槛**即可挡住
2. 用户篡改系统时间绕过有效期 → 需**时间源校验 + 到期宽限**
3. 用户拷贝他人已激活目录/注册表 → 需**设备绑定**
4. 用户反编译 JS 提取密钥算法 → 需**密钥由服务端签发 + 非对称/一次性验证**（纯前端无法根除，只能提高门槛）
5. 专业破解 → 超出离线方案能力，需代码混淆 + 服务端强制在线（可选增强）

## 三、授权激活体系（阶段 1 · 最优先）

沿用已确认方向：**每客户一密钥 + 密钥带截止日期 + 在线激活后离线可用**。

### 3.1 总体流程
```
[管理员] 生成密钥(含客户+截止日) ──存─→ [你的服务器]
                │                            │
                ▼                            │
[客户] 拿到密钥 → 打开 exe → 激活窗口输密钥
        │  ├── 联网：POST /api/license/activate {key, deviceId, deviceName}
        │  │        服务器校验 → 返回 {ok, expiresAt, deviceBound}
        │  │        首次激活：记录 deviceId（绑定设备）
        │  │        已绑定其他设备：拒绝/提示
        │  └── 离线兜底：本地已有激活且未到期 → 直接可用
        ▼
本地保存 {key(散列), expiresAt, deviceId, activatedAt, 签名}
每次启动：检查 expiresAt；能联网时向服务器同步状态（可吊销）
到期 → 锁死，重新激活
```

### 3.2 需要你提供的（关键决策）
1. **后端接口地址**：exe 激活时请求哪个 URL？（例 `https://你的域名/api/license/activate`）
2. **接口由谁实现**：
   - 你的后端已存在（box-wms 那套）→ 我给你接口规范（请求/响应 JSON），你实现
   - 需要现成的 → 我可以按 Cloudflare Pages Functions / Node 给你接口代码模板
3. **密钥表结构**：服务器至少存 `{key, customer, activatedAt?, deviceId?, expiresAt, revoked}`

### 3.3 exe 端我负责实现
- 激活窗口 UI（首次/到期/吊销时弹出，锁主界面）
- 本地激活状态存储（加密 + 自校验，防直接改 localStorage）
- 启动到期检查 + 时间篡改防护（记录最近合法时间、偏差检测）
- 联网同步（能联网时校验/吊销；断网用本地到期日兜底）
- 设备指纹生成（machineId：主板/磁盘/系统组合散列）
- 密钥发放工具（管理员生成"客户-密钥-截止日"CSV）

### 3.4 防篡改要点（离线部分的现实边界）
- 激活状态存 exe 的 userData 目录，加**校验签名**（HMAC，密钥内置于 exe——能被逆向，但防普通改动）
- 到期判断**双源**：本地记录 + 服务器时间（联网时校准）
- 说明：彻底防破解需要服务端强制在线 + 代码混淆，按业务价值取舍

## 四、应用加固（阶段 2）

### 4.1 导入文件校验（app.js）
- file input 加 `accept=".xlsx,.xls,.json"` 
- JS 校验：扩展名 + `file.size` 上限（如 ≤10MB）+ `FileReader` 解析前 try/catch
- JSON 导入：校验必需字段（`paperConfig`/`version`），非法即拒

### 4.2 XSS 审计补漏
- 全量审计 `innerHTML` 中 7 处未带 `escapeHtml` 的拼接点，确认数据源可信或补转义
- 渲染导入的纸名/工艺名/备注等一律 `escapeHtml`

### 4.3 CSP 微调
- 保留当前 CSP；若启用在线激活，`connect-src` 增加后端域名（`connect-src 'self' https://你的域名`）
- 移除 `style-src 'unsafe-inline'` 需重构内联样式 → 成本高，暂不强制

## 五、数据安全（阶段 2-3）

| 方案 | 说明 |
|---|---|
| 价格防篡改 | 本地价格加**弱校验**（HMAC 摘要），检测到被改提示"数据异常"；纯前端可被绕过，属提示级 |
| 报价单导出 | 如需 PDF/图片报价单防伪，加不可见水印（客户名+单号） |
| 备份恢复 | 现有本地备份/JSON 导出已够；建议提醒用户定期导出到 U 盘/网盘 |
| 日志脱敏 | 若加使用统计，不采集客户报价内容，只采匿名激活/版本 |
