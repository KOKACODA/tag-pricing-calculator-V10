## 一、项目背景与定位

KOKALabel 是一家吊牌印刷厂，销售日常需要根据「纸张材质 + 展开尺寸 + 批量档位 + 附加工艺 + 吊绳 + 收货地区」快速给客户报价。此前靠 Excel 查表+心算，效率低且易错。本系统把整套价目表数字化：

- **输入**：批量档位（500~50000 张）、纸张数量（1~N 款同单）、每款纸张的材质/宽/长、附加工艺、吊绳类型、收货地区
- **输出**：各纸张规格表（尺寸/面积/代码/单价）、报价明细（纸张原价/折后价/工艺/吊绳/邮费）、多客户层级报价卡（普通/优质/大客户）、成本合计
- **支撑**：报价归档（客户名+备注+历史查询）、Excel 导出、配置导入导出、多账号协作、云端默认数据分发

## 二、技术形态与规模

| 维度 | 内容 |
|---|---|
| 架构 | 纯前端 SPA（零框架零构建零依赖），可选 Cloudflare Pages（Functions + KV）做账号与云共享 |
| 代码量 | index.html ~1140 行 + app.js ~4600 行 + data.js ~10700 行 + style.css ~3100 行 + auth.js ~300 行 ≈ **2 万行** |
| 数据量 | 1 楼 33 组 + 3 楼 10 张纸、工艺 36 组、吊绳 27 组、邮费 9 地区 |
| 兼容 | Chrome/Edge 桌面 + 移动浏览器；file:// 离线可用 |
| 版本管理 | git 全历史 + tag 逐版本 + 三重归档（KL\V9、9ge tebieban、GitHub 私有仓） |

## 三、功能全景（v9.9.0 现状）

### 3.1 智能报价计算器（核心页）
- 顶部工具条：直接系数计算/标准报价切换、报价表组快捷切换、默认报价显示开关
- 报价条件：批量档位 / 纸张数量 / 收货地区（一行三列）
- 纸张设置：**SKU 芯片直选**（v9.7 起替代渐进下拉，33 材质一排排点选，全称悬浮）、宽/长输入（自动 3mm 出血）、附加工艺芯片
- 吊绳类型：27 组芯片（右上角显示 1000 档基准价）
- 报价结果（右栏 sticky）：规格表格（含面积系数过程 `¥130.00 × 1.27 = ¥165.10`，v9.8）、七行明细（档位/纸张原价/纸张折后价/工艺/吊绳/吊牌成本/邮费）、面积系数提示行、档位快捷按钮、多客户层级价格卡、临时毛利系数、邮费快速修改、报价归档
- **UI 架构双模式（v9.8）**：桌面/iPad = 左侧导航竖栏 + 双栏宽泛式；手机 = 顶部横条 + 单栏卡片纵排（垂直纵深式）；个人主页可手动切换

### 3.2 报价表组查询
- 全部报价表组的纸张/工艺/吊绳价格表展示与**内联编辑**（编辑历史+快照恢复+历史追溯）
- 多报价表组管理（新增/切换/删除/导入导出）
- 超管专属：「↑保存为全局默认（云端共享）」
- 手动代码档位切换（▲▼ 上调/下调代码档）

### 3.3 个人主页
- 报价设置：默认档位/默认吊绳/默认纸张/默认尺寸类型（单张/展开，v9.6 全局化）/小数位/**UI 架构模式（v9.8）**
- 客户层级管理：层级改名 + 系数设置（对应报价卡）
- 本地备份 / 完整配置导入导出 / 报价历史与归档管理
- 账号管理（超管/管理员）：子账号增删改、角色、停用、昵称密码

### 3.4 账号与云同步（网页版）
- 四级角色：superadmin > admin > sales > visitor；权限矩阵严格（sales 全页只读、visitor 仅计算器、管理员互管不删自己、保留 ≥1 管理员）
- 登录 PBKDF2 100K 哈希；会话 KV 管理
- 云端默认数据：超管发布 → KV q:v1 → **全角色 10 秒轮询自动同步**（v9.4.1~v9.4.3 演进而来）→ toast 提示后自动刷新

### 3.5 数据可靠性设计
- dataVersion 迁移链：老用户 localStorage 数据结构升级全自动、幂等（verCompare 守卫）
- 内联编辑历史 + 快照恢复（防误改价）
- 生产包三重归档（本地文件夹 ×2 系 + GitHub）

## 五、重大决策记录（为什么这么做）

1. **v9.4.6 基线归位（09-09）**：v9.5.0~v9.5.2 两轮 UI 重构用户体验不佳（折叠交互/视觉不适），用户拍板废案——但**保留 v9.5.1 的 1 楼 33 组数据更新**。界面与数据解耦处理，形成 main-work 基线。废案分支/tag/归档全部保留不删除。
2. **v9.7 架构转向（09-08）**：用户明确新方向——「垂直纵深式 → 扁平化宽泛式」「渐进式卡片 → 平铺直列」「弱化动态组合、强化预设 SKU 快速点选」「导航不在顶部」。落地为左侧 sidenav + 双栏 + SKU 芯片直选。原则仍是换皮不换骨。
3. **v9.8 双架构共存**：用户要求手机用回垂直纵深式、桌面/iPad 用扁平化。选择「同一 DOM + body class 切换」而非两套 DOM——避免重复 id 和双份逻辑，纯 CSS 切换零业务侵入。UI 偏好存 localStorage 而非 appProfile（避免云同步跨设备互相干扰）。
4. **v9.9 吊绳倍数制**：业务规则变更——吊绳成本相对固定，以 1000 张为基准，500 同价，其余按倍数。副产品：解决了旧逻辑"非标档位（3500/7500）查不到价"的缺陷。
5. **v10.0~v10.3 连续迭代（09-10 晚）**：用户当日连续提出 13 项调整，形成 4 个版本，主题为「可用性细化 + 权限下沉 + 品牌升级」：
   - v10.0 默认模式切换为标准报价（更符合销售主流程）、序号可隐藏、标题显眼化；
   - v10.1 品牌升级（KOKALabel→亲成 + 新 logo 全套图标）、个性化字号（面向全员，含中老年用户）、吊绳折叠、材质下拉双模式（兼顾新老操作习惯）；
   - v10.2 修正**工艺费计价口径**（业务规则：工艺费必须并入纸张后再打折——此前工艺不打折）、表头编辑能力下沉到管理员（超管可视化增删改档位）；
   - v10.3 修复折叠引入的布局回归、表头编辑改为表内内联（与改价格同款交互，降低学习成本）。
6. **品牌换名不动内部标识符**：KOKALabel→亲成 只改显示文案；KOKA 对象、KOKA_AUTH KV、tagPricing_ 存储前缀一律保持——换名零数据迁移、零云端风险。这是本项目"内部标识符与展示文案分离"原则的又一次实践。
5. **数据与界面分离升级**：v9.5.1 数据更新与界面版本解耦（v9.4.6 = 旧界面+新数据），保证任何界面回退不丢数据升级。

## 六、技术亮点

1. **零依赖单文件架构**：xlsx 库本地化（944KB），CSP 严格（script-src 'self'），file:// 双击即用，无需安装。
2. **迁移链幂等设计**：verCompare 守卫 + 内存/存储双写，20 个版本的localStorage 结构演进零事故（v9.3.1 修复过守卫缺陷后固化）。
3. **全角色 10 秒云同步**：发布→全员生效最长 10 秒，多管理员协同时互见新版。
4. **同 DOM 双 UI 架构**：CSS 变量级切换（body.ui-flat/ui-vertical），移动端 UA 自动 + 手动可覆写。
5. **结构校验习惯**：每次 HTML 重构跑 div 栈式配对 + 关键 id 清单断言 + node --check，重大改动加 node 同作用域模拟验证（如 v9.9 迁移双路径测试）。

## 七、踩坑记录（精华教训）

1. **sed 版本号静默失败**（v9.4.1~v9.5.2 连续 5 个版本版本串没更新成功）→ 永久改用 python 精确替换，且区分 `v=X.Y`/`vX.Y`/`"X.Y"` 三种串形态。
2. **迁移守卫污染**：migrateRename900Paper 的 guard 被 sed 连带改写 → 跳过后续迁移 → 已删除该迁移并固化"迁移不碰版本串"纪律。
3. **SheetJS sheet 名非法字符**：5 个纸张简称含 `/` 导致导出报错 → sanitizeSheetName 过滤 `:\/?*[]` + 31 字符截断。
4. **CSP 拦 blob:**：网页端导出 Excel 0 字节 → CSP 加 blob:。
5. **hosts 屏蔽 GitHub**（09-10 发现）：github.com 全系解析 127.0.0.1 + 本机 443 假服务 → TLS 必挂。绕行：绕代理 + schannelCheckRevoke=false + curloptResolve 固定真实 IP 20.205.243.166。
6. **wrangler v4 不上传 Functions**：必须锁 wrangler@3.114.0。
7. **CF must-revalidate 下 ?v= 缓存参数无实效**：版本串错了功能也不坏，但显示混乱——以 title/线上验证为准。
8. **admin 弱密码**：123456789 持续提醒中。
